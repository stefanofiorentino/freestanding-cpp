Evaluation deck · Decision & feedback request

Strategic rationale

The challenge: firmware is the hard part

Bare-metal devices

Many sensors, controllers, and edge devices have no operating system at all.

Legacy tooling

Today that usually means old C, proprietary runtimes, or heavy dependencies.

Concentrated skill

Firmware knowledge is hard to hire for, hard to reuse, and aging.

The gap: modern engineering practices haven't reached the most constrained hardware.

The opportunity

One language, a subset that runs with no OS

C++ is already the language of performance-critical software. C++23 formally defines which library facilities work without a runtime, an OS, or a heap.

Same skills

1×

the language and skill set the team already has

Minimal footprint

0

runtime, OS, or heap — only what the standard allows

Not vendor-locked

✓

hardware- and SDK-independent by construction

What we built

A freestanding-only core that proves the approach

How it works

  • Core compiled with strict guardrails — forbidden from anything outside the freestanding subset
  • No console, no allocation, no exceptions — it could run on bare metal
  • A host-run test suite links against it to prove it compiles, links, and behaves

Proof point: build & tests pass — the core and its verification are real, not a slide.

$ cmake --build build
$ ctest --test-dir build --output-on-failure
100% tests passed
✓ compiles · links · runs freestanding
Why it matters

Three business benefits from one capability

Reuse

One codebase, one skill set across products — from cloud to bare metal. Less context switching, faster time-to-market.

Reliability

No hidden runtime or heap to fail at 2am. Compile-time checks catch whole classes of bugs before the device ships.

Portability

Hardware-independent by construction. Change vendors or parts without rewriting the core.

A small investment today in a capability the team already half-owns.
